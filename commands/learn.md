Teach me this topic: **$ARGUMENTS**

Use the `frontend-system-design` skill's knowledge base.

1. Open the skill's `references/knowledge/INDEX.md` and find the closest roadmap topic. If several match, list them and pick the best; ask only if the topic is genuinely ambiguous.
2. **If the note is written** (`references/knowledge/<file>.md`), teach from it. Notes are long, so don't load the whole file: line 2 maps each section to a line range. Read one section at a time, just before you teach it, in this order:
   1. **ELI5:** the analogy and the one-line takeaway.
   2. **Core concept:** 3–6 key steps, reusing the note's diagrams (Mermaid or ASCII).
   3. **Real-world example:** the most useful code example from the note, explained.
   4. **Why it matters when building:** connect it to the design decisions listed in INDEX.md's "Informs" column. Example: "this is why we preload the LCP image".
   5. **Quiz:** ask 3 of the note's questions one at a time. Wait for my answer, then explain using the note's answer.
3. **If the topic is planned but not written yet,** say so. Then teach it from the skill's `references/core/` and `references/platforms/` files, in the same structure, and cite authoritative sources (MDN, web.dev, the official docs).
4. Finish with:
   - the related notes from the roadmap, both previous and next;
   - a one-line suggestion for applying the topic in my current project, if a project is open.

Keep it conversational and concise. Don't paste the whole note; link it. Teach what the note says: if I ask about something the note doesn't cover, say so, answer from general knowledge labelled as such, and point to the official docs.
